## 1. Context — vì sao làm, làm cho ai

Một web app vừa là **editor pixel art** vừa là **chatbot**. Người dùng mô tả bằng lời, AI tạo ảnh pixel art. Sau đó họ sửa tiếp bằng chat ("đổi áo sang đỏ", "thêm thanh kiếm", "xoá nền") hoặc tự vẽ trên lưới pixel. Ảnh cuối **dùng được ngay cho sản phẩm thật**.

**Đã chốt với bạn:**
| Chủ đề | Quyết định |
|---|---|
| Mục đích sử dụng | Hỗ trợ cả 4 loại: asset game · in lên sản phẩm (POD) · ảnh số/social · mẫu thủ công (bead/thêu) |
| Quy mô | Hướng tới SaaS, **trước mắt làm MVP deploy cho test user** |
| AI | **Dùng API trước**. Code phải mở rộng được sang model local/GPU khi có vốn |
| Nhân lực | **1 người + AI hỗ trợ** (Claude Code) |
| Máy dev | i7-10750H, RAM 16GB, GTX 1650 4GB. Đủ để dev toàn bộ app. Chỉ chạy được SD1.5 cho nhánh thử model local |

**Mục tiêu MVP:** test user tạo → sửa (bằng chat hoặc tay) → xuất file đạt chuẩn cho ít nhất 1 preset của mỗi mục đích.

**Các quyết định mình tự đưa ra — bạn kiểm lại khi đọc:**
- Kiến trúc A: TypeScript monorepo. Model local sau này là service Python riêng.
- Claude `claude-opus-5-5` cho chatbot, vòng lặp tool do app tự chạy, bọc sau interface để sau đổi được LLM.
- Chỉ dùng chế độ màu indexed (≤256 màu).
- AI tạo/sửa ảnh ra layer mới (không ghi đè). Lệnh có quy tắc áp ngay và Ctrl+Z hoàn tác được.
- Trình duyệt giữ bản chuẩn của doc. Tool AI chờ job xong, tối đa 120 giây.
- Hạ tầng: Railway + Neon + Cloudflare R2. Đăng nhập: Better Auth (Google + magic link). MVP chỉ vào bằng mã mời.
- Nhánh model local (L1–L4) là tuỳ chọn, không chặn MVP.

**Không làm trong MVP:** thanh toán, làm việc nhóm/real-time collab, editor animation đầy đủ, mockup sản phẩm, app mobile, tự host GPU cho production.

**Coi là thất bại (dù chạy được):**
- Ảnh AI "giả pixel": lệch lưới, viền mờ, hàng trăm màu.
- Người dùng mất quyền kiểm soát: AI ghi đè lên tác phẩm mà không hoàn tác được.
- Chi phí API vượt kiểm soát vì không có hạn mức.

## 2. Ý tưởng cốt lõi (rút ra từ khảo sát)

1. **Dùng API chuyên pixel art cho việc tạo ảnh.** Retro Diffusion có `rd-fast`, `rd-plus` (~$0.18/ảnh), `rd-tile`, `rd-animation` (xuất sprite sheet), và tham số `input_palette` để ép bảng màu. PixelLab có tạo ảnh, animation, inpainting. Các API này cho pixel art sạch hơn model đa năng.
2. **Dùng model đa năng cho việc sửa theo lời.** Ví dụ FLUX Kontext, Nano Banana, GPT Image qua fal.ai. Ảnh của chúng chỉ "trông giống" pixel art, nên **mọi ảnh phải qua bộ chuẩn hoá pixel** (mục 4.4).
3. **Lớp `ImageProvider` chung + nhiều adapter.** Đổi hoặc thêm nhà cung cấp, kể cả GPU local, không phải sửa app.
4. **Chia việc cho chatbot theo loại lệnh:**
   - Lệnh có quy tắc rõ ràng (đổi màu, thêm viền, lật, resize, giảm màu, xoá nền) chạy bằng code trong `pixel-core`. Kết quả tức thì, miễn phí, chính xác tuyệt đối.
   - Chỉ lệnh cần hiểu nội dung mới gọi model ảnh.
5. **AI không bao giờ ghi đè trực tiếp:**
   - Kết quả của lệnh tạo/sửa bằng AI là một **đề xuất**: layer tạm hoặc các biến thể, người dùng bấm Accept/Reject.
   - Lệnh có quy tắc được áp ngay, nhưng luôn hoàn tác được (undo).
   - Mỗi thay đổi tạo một phiên bản (version).

## 4. Thiết kế chi tiết

### 4.1 Định dạng tài liệu chuẩn — `PixelDoc` (`packages/shared` + `pixel-core`)

```ts
PixelDoc {
  version: 1, width, height,            // tối đa 256×256 trong MVP
  palette: string[]                     // RGBA hex, index 0 = trong suốt, ≤256 màu
  layers: { id, name, visible, opacity, locked }[]
  frames: { id, durationMs }[]          // MVP: ≥1 frame; có frames để nhập animation từ AI
  cels:   { layerId, frameId, data }[]  // data = base64(RLE(Uint8Array chỉ số palette))
  meta:   { purpose: 'game'|'print'|'digital'|'craft', pixelGrid?: number, tags?: … }
}
```

**Chế độ màu chỉ số (indexed)** là chế độ duy nhất. Nhờ vậy ảnh luôn có số màu giới hạn và luôn đúng palette, điều kiện tiên quyết cho "ready to product".

Snapshot được nén (gzip) và lưu ở Postgres `bytea`, tối đa 2MB.

### 4.2 Editor (apps/web)

- **Canvas 2D:**
  - Zoom theo số nguyên, pan, lưới pixel, nền caro thể hiện vùng trong suốt.
  - Ô xem trước ở kích thước 1×.
  - Chỉ vẽ lại vùng thay đổi (dirty-rect) để giữ hiệu năng.
- **Công cụ:**
  - Bút (cỡ 1–4), tẩy, đổ màu (vùng liền / toàn ảnh), line, rect, ellipse, eyedropper.
  - Chọn vùng (chữ nhật / lasso / magic wand) và di chuyển vùng chọn.
  - Vẽ đối xứng X/Y, thay màu hàng loạt.
- **Palette:**
  - Các preset có sẵn; thêm/sửa/khoá màu; hiển thị số màu đang dùng.
  - Đổi palette có tuỳ chọn dither.
- **Layers:** thêm, xoá, đổi thứ tự, ẩn/hiện, opacity, merge.
- **Frames (MVP tối giản):** danh sách frame, phát thử, onion skin. Mục đích chính là hiển thị animation do AI tạo.
- **Undo/redo:** dùng command pattern, mỗi command lưu patch các pixel đổi. Phím tắt giống Aseprite.
- **Tạo canvas mới theo mục đích:**
  - game: 16/32/64
  - print: 64–128
  - digital: 32–128
  - craft: kích thước theo số bảng ghim 29×29
- **Lưu:** tự lưu (debounce) thành version. Dùng optimistic concurrency theo `versionId` để không ghi đè khi có xung đột.
- **Khung đề xuất AI:** layer tạm, nút so sánh trước/sau, Accept / Reject / Thử lại. Khi AI trả nhiều biến thể thì hiện dạng lưới để chọn.
- **Bấm Accept** (call của mình — không phá huỷ bản vẽ):
  - Kết quả được thêm thành **layer mới** "AI: <mô tả>" ngay trên layer đang chọn. Người dùng tự merge xuống nếu muốn.
  - Với `edit_image` theo vùng chọn, kết quả bị cắt theo đúng mask.
  - Job chạy lâu không xung đột với nét vẽ người dùng thêm trong lúc chờ, vì kết quả luôn vào layer mới.
- **Xử lý palette khi Accept:**
  - `keep_palette` (mặc định khi sửa): ép kết quả về palette hiện tại của doc.
  - Tạo ảnh trên canvas trống: doc nhận luôn palette của ảnh vừa tạo.
  - Tạo ảnh trên canvas đã có hình: gộp màu mới vào palette. Nếu vượt giới hạn màu người dùng đặt thì ép về palette hiện tại.
- **Nối editor với chat:**
  - Chọn vùng → bấm "Hỏi AI về vùng này" để gửi mask kèm câu lệnh.
  - Có các chip lệnh nhanh: Xoá nền · Thêm viền · Giảm còn 16 màu · Ảnh → pixel.

### 4.3 Chatbot (packages/agent + apps/api)

- **Gọi Claude:**
  - Dùng **Claude Messages API, vòng lặp tool do app tự chạy trong apps/api**.
  - Bọc sau interface `LLMProvider`, để sau này đổi sang LLM khác hoặc LLM local được.
  - Có cân nhắc Managed Agents (Anthropic chạy vòng lặp) nhưng không chọn: tool phải thao tác trên DB/doc của app, và vòng lặp cần đổi được nhà cung cấp.
- **Cấu hình:**
  - Model mặc định `claude-opus-5-5`, đổi được qua env `CHAT_MODEL`.
  - `thinking: {type: "adaptive"}`, `output_config.effort` mặc định `low` cho lượt chat (chỉnh được theo route).
  - Streaming, `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`).
  - Prompt caching cho system prompt và danh sách tool.
  - Xử lý `stop_reason: "refusal"`.
  - Mỗi lượt tối đa 8 lần gọi tool.
  - Lưu nguyên các content block, kể cả thinking block, để gửi lại đúng như cũ ở lượt sau.
- **Context gửi kèm mỗi lượt:**
  - Tóm tắt doc: kích thước, palette, danh sách layer, vùng đang chọn.
  - Ảnh canvas phóng to bằng nearest-neighbor lên ~512px, để Claude "nhìn" được.
  - Lịch sử chat.
- **Tool** (schema zod, `strict: true`). Không dùng forced `tool_choice` vì Opus 5.5 không hỗ trợ.

  | Loại | Tool |
  |---|---|
  | AI tạo/sửa (ra **đề xuất**) | `generate_image{prompt,width,height,palette?,style?,purpose,variants 1–4,reference_asset_id?}` · `edit_image{instruction,region:'selection'\|'all',keep_palette}` · `animate{action,frames,direction?}` |
  | Có quy tắc (áp ngay, undo được) | `recolor` · `apply_palette{preset\|colors,dither}` · `reduce_colors{n}` · `add_outline{color,mode}` · `remove_background` · `resize_canvas` · `scale` · `flip` · `rotate90` · `crop_to_content` · `shift_hue` |
  | Khác | `export_asset{preset}` · `get_canvas_info` |

- **Đồng bộ doc giữa trình duyệt và agent** (call của mình):
  - **Trình duyệt giữ bản chuẩn.** Mỗi tin nhắn chat gửi kèm snapshot doc hiện tại + `baseVersionId`. Doc nhỏ nên gửi được, và agent luôn thấy cả nét vẽ chưa lưu.
  - Tool chạy trên snapshot đó ở server rồi trả kết quả qua SSE, theo một trong hai dạng:
    - `doc_patch` (tool có quy tắc): client áp thành **1 command trong undo stack**, đặt tên kiểu "AI: thêm viền", nên Ctrl+Z hoàn tác được.
    - `proposal` (tool AI ảnh): hiện để người dùng chọn.
  - Nếu người dùng sửa đúng vùng đó trong lúc lượt chat đang chạy, `doc_patch` chuyển thành `proposal` thay vì tự áp.
- **Luồng xử lý tool AI:**
  1. Tool tạo job, giữ trước credit (reserve).
  2. Tool **chờ job xong** (timeout 120 giây) và stream sự kiện `job_progress` cho người dùng xem.
  3. Xong thì Claude nhận tóm tắt (số biến thể, `gridConfidence`) + thumbnail để tự đánh giá rồi trả lời.
  4. Nếu quá timeout, tool trả `{status:"running"}`. Đề xuất vẫn được đẩy tới FE khi job xong. Lượt chat sau có thêm một ghi chú hệ thống về kết quả đó.
- **Guardrails:**
  - Kiểm duyệt nội dung: system prompt + bộ lọc moderation của provider.
  - Tool chỉ chạm được project của chính người dùng.
  - Ảnh và text người dùng tải lên được coi là dữ liệu, không phải lệnh.
  - Kiểm tra credit trước khi enqueue.

### 4.4 Lớp AI ảnh + chuẩn hoá pixel (packages/providers, packages/pixel-core)

```ts
interface ImageProvider {
  id: string
  capabilities: { generate; edit; inpaint; animate; tileset; nativePixel: boolean; maxSize; paletteInput: boolean }
  generate(req): Promise<ProviderResult>; edit?(req); animate?(req)
  estimateCost(req): { usd: number; credits: number }
}
```

**Router** chọn provider theo: loại việc → capability → cấu hình (env / feature flag) → chuỗi fallback khi lỗi. Mỗi provider có giới hạn tốc độ và số job đồng thời riêng.

**Adapter cho MVP:**
- `retrodiffusion`: chính cho tạo ảnh, tileset, animation.
- `fal`: sửa ảnh theo lời. Chọn 1 model qua đánh giá ở P2.
- `mock`: ảnh fixture, $0, dùng cho dev và CI.
- `pixellab`: tuỳ chọn, cho inpainting.

**Bộ chuẩn hoá pixel** (`normalize()`, hàm thuần, chạy được cả browser lẫn worker):
1. Decode ảnh thành RGBA.
2. Làm sạch alpha: alpha chỉ còn 0 hoặc 255. Nếu nền không trong suốt thì xoá nền bằng flood-fill từ mép ảnh (color key), hoặc gọi API tách nền.
3. **Dò lưới:** dựa vào phân bố độ dài các dải cùng màu (run-length) và autocorrelation theo hai trục x/y, ước lượng `blockSize` và `offset`.
4. **Thu nhỏ:** mỗi ô lưới lấy **màu xuất hiện nhiều nhất** (mode), không lấy trung bình, để không sinh màu lai.
5. **Lượng tử hoá màu:**
   - Có palette đích: map mỗi màu tới màu gần nhất trong OKLab.
   - Không có: chạy k-means trong OKLab về N màu (mặc định 16 hoặc 32).
6. Dọn dẹp: xoá pixel lẻ (tuỳ chọn), thêm viền (tuỳ chọn).
7. Trả về `PixelDoc` + các chỉ số chất lượng `{gridConfidence, colorCount, alphaClean}`. Chỉ số này dùng cho eval, và tự thử lại khi `gridConfidence` thấp.

Cùng pipeline này phục vụ tính năng **"Ảnh chụp → pixel art"** (không cần AI).

### 4.6 Backend: API, job, dữ liệu

**API** (REST + SSE, có OpenAPI):
- Auth: Better Auth handler.
- `projects` CRUD.
- `GET|PUT /projects/:id/doc` (PUT kèm `baseVersionId`).
- `GET /projects/:id/versions`, `POST …/versions/:vid/restore`.
- **`POST /projects/:id/chat` → SSE.** Các sự kiện trả về: `text_delta`, `tool_start`, `job_progress`, `proposal`, `done`, `error`.
- `GET /jobs/:id/events` (SSE).
- `POST /assets/upload-url` (presigned PUT lên R2).
- `POST /projects/:id/exports` → job → URL tải có ký.
- `GET /me`, `GET /me/credits`, `POST /feedback`.
- Admin: `/admin/usage`, `/admin/invites`.

**Job** (BullMQ trên Redis):
- 3 queue: `ai-generate`, `ai-edit`, `export`.
- Retry với backoff, idempotency key, timeout.
- Tiến độ được publish qua Redis pub/sub rồi đẩy xuống client bằng SSE.

**Bảng dữ liệu** (Drizzle):
- Các bảng của Better Auth.
- `projects`, `doc_versions(parent_id, snapshot bytea, source user|ai|import)`.
- `chat_threads`, `chat_messages(content jsonb, usage jsonb)`. `usage` lưu token và USD để tính credit và đối soát chi phí.
- `jobs(type, provider, model, status, input, output, cost_usd, credits, error, timestamps)`.
- `assets(kind upload|provider_raw|result|export|thumbnail, r2_key, mime, w, h, bytes)`.
- `plans(id, name, allowance_amount, allowance_period day|week|month, price)`: MVP có `free` và `tester`.
- `credit_accounts(user_id, plan_id, allowance_balance, period_start, period_end, purchased_balance)`.
- `credit_holds(id, user_id, amount, split_allowance, split_purchased, status held|committed|released, expires_at)`: dùng cho bước giữ trước → trừ thật → hoàn lại.
- `credit_ledger(user_id, bucket allowance|purchased, delta, reason reset|chat_turn|job|refund|admin_grant|topup|expire, ref_id, meta)`. Đây là sổ cái chỉ thêm, không sửa; số dư phải luôn đối soát được với nó.
- `credit_requests(user_id, message, created_at)`: lưu yêu cầu "cần thêm credit" ở MVP.
- `invites(code, max_uses, used, plan_id, bonus_credits)`, `feedback`.

### 4.7 Auth, credit, chống lạm dụng

- **Auth:** Better Auth, đăng nhập bằng Google OAuth hoặc magic link email (gửi qua Resend). **MVP chỉ cho vào bằng mã mời.**
- **Credit kiểu Modal** (đã chốt với bạn): có sẵn một lượng credit free, dùng hết thì phải trả thêm, credit free reset theo chu kỳ.
  - **Hai "ví" credit cho mỗi user:**
    - **Credit free (allowance):** mỗi gói có một mức cố định, ví dụ gói Free 100 credit/tháng. **Reset về đúng mức đó khi hết chu kỳ.** Chu kỳ tính từ ngày đăng ký và cấu hình được: ngày / tuần / tháng. Phần không dùng hết thì không cộng dồn sang kỳ sau.
    - **Credit mua thêm (purchased):** nạp trước, không reset. Hạn dùng mặc định 12 tháng (cấu hình được).
  - **Thứ tự trừ:** dùng hết credit free trước, sau đó mới trừ sang credit đã mua.
  - **Reset kiểu lazy:** mỗi lần đọc hoặc trừ credit, nếu `now ≥ period_end` thì reset ngay. Thêm một job BullMQ chạy hằng ngày để reset tài khoản không hoạt động và gửi email "credit đã được làm mới". Không phụ thuộc cron để tính đúng số dư.
  - **Giá:**
    - **Mỗi lượt chat: 1 credit.** Giữ trước khi gọi Claude, hoàn lại nếu lỗi hoặc bị từ chối (refusal).
    - **Mỗi job ảnh: 5–10 credit** tuỳ loại. Giữ trước khi enqueue → trừ thật khi thành công → hoàn lại khi lỗi.
    - Giá credit chính thức chốt ở P2, khi đã có số liệu chi phí thật. Chi phí thật (token + USD) được ghi vào `credit_ledger.meta`.
  - **Màn hình credit** (giống trang usage của Modal):
    - Header luôn hiện "Còn X credit free · reset sau N ngày · Y credit đã mua".
    - Báo trước khi còn dưới 20%.
    - Trang lịch sử dùng credit theo ngày, chia theo loại (chat / tạo ảnh / sửa ảnh / export).
  - **Hết credit:**
    - Ô chat và nút AI hiện "Hết credit — reset vào <ngày>" kèm nút **Mua thêm**.
    - **MVP chưa có cổng thanh toán.** Nút Mua thêm mở form "Cần thêm credit" để ghi nhận nhu cầu trả tiền. Admin cấp credit tay (ghi vào ví purchased, `reason=admin_grant`).
    - Cổng thanh toán thật (gói credit nạp trước qua Polar / Lemon Squeezy / Paddle hoặc PayOS / VNPay) nằm ở P6. Webhook thanh toán ghi `reason=topup` vào ví purchased. Muốn kéo phần này lên làm trước khi mở cho test user thì làm ở cuối P5, khoảng +1 tuần.
  - **Gói (plan):**
    - MVP có gói `tester`, mức credit free cao hơn, gán qua mã mời.
    - Sau này có gói trả phí theo tháng (subscription) với mức free lớn hơn, cùng cơ chế reset.
- **Chặn chi phí:**
  - Trần chi tiêu toàn hệ thống `MAX_DAILY_PROVIDER_USD`, tính **cả chat lẫn job ảnh**.
  - Có **kill switch** tắt tính năng AI bằng env hoặc feature flag.
  - Rate limit theo user và IP (Redis).
- **Bảo mật:**
  - Bucket R2 để private, truy cập bằng URL có ký.
  - Ảnh upload: kiểm tra mime + giới hạn 10MB + encode lại.
  - API key của provider chỉ nằm ở server.
- **Thanh toán (giai đoạn SaaS, sau MVP):** ưu tiên bên merchant-of-record (Polar / Lemon Squeezy / Paddle), vì Stripe chưa hỗ trợ pháp nhân Việt Nam trực tiếp. Có thể thêm PayOS / VNPay / MoMo nếu nhắm người dùng Việt Nam.

### 4.8 Deploy & vận hành

- **Local:**
  - `infra/docker-compose.yml` chạy Postgres 17, Redis 7, MinIO.
  - `pnpm dev` (Turborepo) chạy cùng lúc web + api + worker.
  - Mặc định `PROVIDER=mock`, nên dev không tốn tiền.
- **Môi trường:**
  - `staging`: tự deploy khi merge vào `main`.
  - `production`: deploy khi tạo tag `v*`, có bước duyệt tay.
- **Hạ tầng MVP:**
  - **Railway:** web + api + worker + Redis, chạy container từ Dockerfile.
  - **Neon:** Postgres, có backup/PITR và tạo branch DB theo PR.
  - **Cloudflare R2:** lưu ảnh, không mất phí egress.
  - **Cloudflare:** DNS.
  - Mọi thứ đều có Dockerfile, nên chuyển sang Fly hoặc VPS (Hetzner + Coolify) dễ dàng.
- **CI/CD (GitHub Actions):**
  - Mỗi PR: lint, typecheck, vitest, build, Playwright e2e (docker compose + provider mock).
  - Khi deploy: chạy `drizzle-kit migrate` làm release command, sau đó chạy smoke test.
- **Giám sát:**
  - Sentry: lỗi FE + BE.
  - PostHog: analytics, feature flag, khảo sát/feedback.
  - Log dạng JSON bằng pino.
  - Uptime check: Better Stack hoặc UptimeRobot, gói free.
  - Trang admin hiển thị chi phí provider theo ngày và theo user, tổng hợp từ bảng `jobs`.

### 4.9 Nhánh L — model local/GPU (tuỳ chọn, song song nhẹ, không chặn MVP)

- **L1 — trên laptop GTX 1650:**
  - Dựng `services/gpu-inference` (FastAPI + diffusers) chạy SD1.5 + LoRA pixel art, fp16, chế độ ít VRAM.
  - Hợp đồng HTTP: `POST /generate`, `POST /edit`, trả về PNG.
  - Viết adapter `local-gpu`.
- **L2 — so sánh model trên Colab/Kaggle free** (chỉ chạy offline, không host web service). Các ứng viên: SDXL + LoRA, FLUX.1-schnell, Qwen-Image(-Edit). **Không dùng FLUX.1-dev** vì cấm thương mại.
- **L3 — host thật:**
  - Deploy cùng service đó lên **Modal** (credit free $30/tháng, tự tắt khi không có request), hoặc RunPod Serverless.
  - Bật cho người dùng qua feature flag, A/B với API trên bộ `evals/`.
- **L4 — khi có vốn:** fine-tune LoRA riêng trên dữ liệu có bản quyền rõ ràng, thuê RTX 4090 trên Vast/RunPod (~$0.3–0.5/giờ).

## 9. Kiểm chứng (verification)

- **pixel-core:**
  - Golden-image test so khớp từng pixel trên bộ ảnh fixture.
  - Property test: mọi pixel thuộc palette, số màu ≤ N, alpha chỉ 0 hoặc 255, kích thước đúng.
- **providers:** contract test với fixture đã ghi sẵn (CI không gọi mạng). Adapter `mock` dùng cho dev và e2e.
- **credit:** unit + integration test cho các tình huống sau:
  - reset lazy khi qua kỳ, không cộng dồn
  - trừ credit free trước rồi mới tới credit đã mua
  - hai request chạy song song không làm số dư âm (khoá hàng bằng `SELECT … FOR UPDATE`)
  - hoàn lại credit khi job lỗi
  - hold hết hạn được tự trả lại
  - số dư luôn khớp với tổng `credit_ledger`
- **api:** integration test với Postgres/Redis thật (docker compose). Vòng lặp agent được test bằng `LLMProvider` giả, phát tool call theo kịch bản.
- **web e2e (Playwright):** đăng nhập → tạo project → vẽ → chat "tạo hiệp sĩ 32×32" (mock) → Accept → "thêm viền đen" → undo → xuất sprite sheet + PNG 300 DPI + PDF mẫu hạt → kiểm tra file.
- **Chất lượng AI:** `pnpm eval` chạy bộ `evals/` trên provider thật (tốn tiền, chạy thủ công). Báo cáo gridConfidence, số màu, độ sạch alpha, kèm bảng chấm tay. Chạy trước mỗi lần đổi provider hoặc model.
- **Kiểm tra export bằng công cụ ngoài:** mở sprite sheet + JSON trong Aseprite/Godot, kiểm DPI bằng exiftool, mở SVG trong Inkscape, in thử PDF mẫu hạt.
- **Smoke test sau deploy:** health endpoint, đăng nhập, 1 job tạo ảnh bằng mock trên staging.

## 10. Để lại cho lúc build (người build tự quyết)

- Model cụ thể của fal cho việc sửa ảnh: chọn bằng bộ eval ở P2.
- Giá credit cụ thể cho từng loại job: chốt sau khi có chi phí thật ở P2.
- Thuật toán dò lưới chi tiết: bắt đầu bằng run-length + autocorrelation, cải tiến theo eval.
- Giao diện chi tiết của editor và chat: phác thảo mockup ở đầu P1.
